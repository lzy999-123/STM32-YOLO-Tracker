## 2. 本次学到的知识

- 原厂程序是硬件参数的证据，不是当前接线的证明 → 原厂PA0/1/2、PB6/7与当前双轴PWM及独立I2C不同 → 对照MCU引脚和同一根电机轴后再决定采用程序。
- 电机反馈先独立验证 → 手转转子观察原始0～4095计数，可区分通信、磁铁和轴配对 → 闭环故障时先断开三相，用被动测角排查。
- 原厂演示电压不等于适合当前负载 → 电机规格书相电阻2.55Ω、额定电流0.5A，当前没有电流采样 → 不用提高电压掩盖传感器或驱动错误。
- 编译成功不证明诊断固件无运动路径 → 新入口复用旧初始化，旧运动入口改名后被链接器移除 → 检查实际映像符号和HAL调用，再交付被动诊断。

## 5. 以后做项目要注意什么

1. 固定并记录同一轴的电机、驱动、编码器对应关系。I2C读取成功仅证明通信，不能证明它测量正确的电机轴。
2. 手动诊断时先整机断电再拔电机三相插头，保留编码器供电和接线，避免断开驱动电源后编码器也失去电源而被误判故障。
3. 被动诊断用独立工程/HEX及清晰OLED标识，检查最终链接映像，避免用户误下载仍包含运动入口的固件。
4. 保护触发证明存在软件判断的异常，不等于已确认机械堵转或某个硬件损坏。先补全实物证据，保留既有保护阈值。
5. 当前运动源码在校准失败出口会把故障改写为ALIGN，因此用户报告DRIVE FAULT也不能唯一定位到校准阶段；按键时序和启动日志仍需核对。
