# 学习报告：视频间歇卡顿的无线链路定位

- 日期：2026-10-10（Asia/Shanghai）
- 本次提交主题：定位无线视频间歇停顿及异常恢复等待（诊断阶段，未提交）
- 修改前基线：`fae9e3166f83c7bb69791ac882ce58a998de21b3`
- 涉及模块：Luckfox 摄像头/ISP/编码器、Wi-Fi、RTSP、CameraManager、MainWindow 显示；新增诊断报告和索引，测量工具与记录位于被忽略的 `tmp/stutter-20261010/`

## 1. 本次目标与完成情况

用户报告画面偶尔卡顿，影响跟踪，并确认“只看画面也会卡顿”。本次在真实 Luckfox 与实际 Qt 窗口中复现，比较摄像头输入、TCP/UDP 到帧、解码、画面翻转、界面显示和事件响应。

**已确认的故障位置：摄像头输入之后、界面显示之前的无线到帧/RTSP 传输阶段。** 摄像头持续约30帧，输入和编码器计数没有新增错误；无线探测出现21%～35%的超时，视频突发到达，板端曾出现视频包丢弃警告，实际解码出现超时和H.264错误。界面单帧显示处理不到3毫秒，事件响应保持在17毫秒以内，不能解释实测数秒的画面停顿。

另一个代码层面的恢复因素：读取超时设置为2秒，失败后在同一会话重试，状态巡检要等超过5秒没有新帧才重新打开视频。它会增加严重断流时的等待，但没有修复无线链路的作用。

诊断已经完成；热点、无线干扰、网卡驱动或无线侧排队之间的具体触发因素尚未通过更换链路的对照确认。本次没有实施码率/网络/超时参数修复，也没有验收消除卡顿。

## 2. 本次学到的知识

- 帧率均值不能代表连续性 → UDP实际到帧间隔最大1.23秒，之后集中到帧 → 同时记录帧间隔、长空档次数和平均帧率。
- 来源时间轴和接收时间轴应分别测量 → UDP视频源相邻RTP时间戳约33.33毫秒，接收间隔却达到数百毫秒 → 用来源节奏、摄像头计数及网络证据定位传输积压，不把RTP时间戳称为同步的端到端延迟。
- 最新帧替换不能消除发送端或无线侧的积压 → Qt解码后只保留最新帧，解码之前仍会停顿或收到滞后的数据 → 跟踪优化要先保证输入及时、完整。
- 同一帧可能有多个RTP marker → 本设备的参数集和图像数据可能共用时间戳 → 按视频时间戳合并后计数，不能直接把marker数量当图像帧数。
- 恢复门槛影响长停顿 → 当前2秒读取超时与5秒无帧重连门槛不同 → 传输稳定性和异常恢复需要分别验证。

| 现象 | 证据与原因 | 处理方法 | 结果 |

| 只看画面也会卡顿 | 用户确认；未开启跟踪、未连接实体控制的Qt诊断窗口仍复现 | 先测视频传输与显示 | 确认问题在跟踪之前已经存在 |
| 画面停一阵后集中更新 | UDP来源间隔33.21～33.46毫秒，接收最大空档1226.99毫秒；86次空档超过100毫秒 | 原始TCP/UDP接收并同步读取摄像头、ISP、网络计数 | 已确认到帧节奏不稳定；UDP也没有消除停顿 |
| 实际Qt解码长时间无帧 | 解码平均15.30帧，最大间隔7344.88毫秒，日志出现约2秒读取超时及H.264宏块错误 | 编译当前源码的诊断副本，记录后台解码与实际绘制事件 | 收流/解码停顿与画面停顿对应，GUI本身持续响应 |
| 怀疑翻转或时间文字耗时 | 实测垂直翻转最大0.55毫秒；包括缩放、文字、绘制和帧分发的单帧处理最大2.97毫秒 | 合成720p输入与真实摄像头分别测量同一显示代码 | 当前画面方向与叠字没有表现出能解释长停顿的耗时 |

| 诊断程序首次启动缺少DLL | 临时EXE没有自己的部署目录，返回`0xC0000135` | 在被忽略的诊断目录引用现有Release依赖，指定Qt与视频插件目录 | 后续合成和真实Qt测量均正常退出0；这是诊断工具部署问题 |

## 5. 以后做项目要注意什么

1. 卡顿先同时记录输入计数、来源时间戳、到达间隔、解码警告、绘制间隔和GUI事件响应，再决定改哪一段。
2. 对无线视频同时检查热点和板子方向；电脑信号很好、RTP序号连续或平均帧率接近30，都不足以证明连续低延迟。
3. 诊断阶段保护已有未提交工作；临时计时副本、二进制、原始日志放在被忽略目录，正式报告只记录必要数值。
4. 30帧视频正常间隔约33毫秒。验证改进时同时报告超过100/200毫秒的空档数量和最大空档，避免只展示FPS均值。

## 6. 当前不足与下一步

- 需要一次有线或更换热点/摆位的对照，进一步区分热点无线侧、环境干扰、网卡驱动与网络排队。当前已定位传输故障，尚未确认其中唯一的物理触发原因。
- 稳定传输后，再单独验证缩短失败读取与无帧重连等待的效果；修改时保留关闭、刷新、切流的会话保护，验证没有重连风暴和旧会话帧回流。
- 还需针对跟踪验证输入过期时不持续使用滞后图像。恢复图像后，应核对目标重新锁定和控制方向；本次没有完成这项实体验收。
- 项目仍处于阶段开发，本文不是消除卡顿验收或项目最终完成报告。
