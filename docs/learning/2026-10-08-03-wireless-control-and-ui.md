## 2. 本次学到的知识

- Designer 删除控件 → 原代码仍引用串口选择框及角度文本框 → 修改布局时应同时审计代码中的对象引用。
- 原生 WLAN API → 后台读取真实 SSID，处理权限不足 → 避免解析依赖语言环境的 netsh 文本。
- Windows 头文件宏 → `interface` 与局部变量重名造成编译失败 → 平台代码采用具体变量名，如 wifiInterface。
- 网络重发与执行去重 → request 相同的手动步进只在 UART 执行一次 → 网络确认丢失不能直接重复驱动硬件。
- 命令 ACK 与设备在线 → socket/视频连通不等于 STM32 有响应 → 控制可用性必须由合法遥测驱动。
- 分层验收 → Wi-Fi 实链路加软件 UART 模拟验证协议 → 实体接线、UART 启用和运动仍需独立验证。

## 4. 验证与证据

- Qt 6.10.1 + MSVC2022 Release：qmake、编译、链接通过，windeployqt 检查通过。
- Python 桥接测试：`python -m unittest discover -s tests -p test_control_bridge.py -v`，10 项通过。
- Qt 网络控制测试：2 个行为测试通过，默认未启用实板隔离用例时该用例标记跳过。
- 单独启用实板隔离用例：Qt bridgeOverWifi 通过；真实热点链路到 Luckfox 的 UDP 5006，软件模拟 STM32。
  结果为 manual_left=1、track_frames=6、last_offset=[-100,50]、dropped_ack=1。
- 真实 GUI：显示 Windows 当前 Wi-Fi、实际发现的 Luckfox 地址和原生 1280×720 画面；无云台遥测时控制禁用。
- 最后一次真实 GUI 运行日志出现显示 FPS 29、31 和解码约 29.63 FPS。这是当前运行窗口的计数，不是固定帧率承诺，也不是端到端延迟。
- 板子 Python termios/fcntl/select 标准库检查和控制脚本编译通过。无配置时启动脚本返回“UART 未配置，未启动”。
- 实板模拟、GUI 日志、截图和结果仅位于忽略的 tmp/；仓库不保存 SSID、热点凭据或摄像头截图。
- 本次没有测量同步端到端延迟；显示 FPS 和模拟 UART 数据不能作为实体云台闭环证据。

## 5. 以后做项目要注意什么

- 为重复控制命令设计去重，而非只增加重发次数；UART 协议不带序号时尤其要区分幂等与非幂等命令。
- 对过期会话和坐标做清理；停止指令应立即清除待转发的旧目标。
- 启用按钮应依赖真实设备遥测，模式以设备回传为准。
- 修改界面后实际运行，检查旧动态控件是否覆盖视频、长名称是否截断、窗口缩放是否影响框选坐标。
- 配置实际 UART 前先检查设备树、系统控制台和接线，避免占用调试端口。
