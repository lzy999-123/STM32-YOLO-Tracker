## 2. 本次学到的知识

- 事件时刻和可用时刻不同 → RTSP retrieve 后的时间只是主机接收/解码完成，Qt startTime 是显示时间 → 不能用这些值冒充曝光时刻。
- 多级最新帧覆盖需要一起传递元数据 → 图像、帧编号和方向必须在同一把缓存锁下复制 → 防止用“最新时间”标注较旧推理结果。
- 异步日志必须显式记录损失 → 有界队列溢出计数、结束标记、序号审计 → 文件存在不等于实验数据完整。
- 近似诊断不能伪装严格验证 → 只使用此前已到达遥测，不用未来信息插值；校准/身份/源时钟未验证时不通过 → 为后续受控实验保留真实证据边界。
- 留出图片重投影也有边界 → 固定内参后仍为每张图拟合姿态 → 小残差不直接证明外部角度精度。

## 3. 遇到的问题与解决过程

| 现象 | 证据与原因 | 处理方法 | 结果 |
| --- | --- | --- | --- |
| 现有链路无源采样时间 | 当前 OpenCV RTSP 与遥测协议均未携带可统一的采样时钟 | 未知字段写 null，单独记录主机时刻；不更改板端协议 | 工具明确输出 synchronized_los_ready=false |
| 最新帧可被覆盖 | CameraManager、GUI 和 DNN 都有最新帧缓存 | 在相同锁内传递 ResearchFrame；加入合并帧与DNN输入身份测试 | 开启日志专项测试通过 |
| 初次测试启动失败 | qmake 单配置输出不在 release 子目录；缺少 Qt ICU/非 Qt 动态库；PowerShell 输出参数引用有误 | 修正测试路径和参数，在独立目录部署运行库 | 不改正式部署目录，重跑成功 |
| 合成或公开图片容易被误当实测 | 单元测试使用合成投影、公开 bus.jpg、localhost 伪设备 | 记录数据来源；不把时延样本写成平台性能结论 | 实推理日志完整性通过，但不声明实机性能 |
| 模型存在 CPU 节点回退 | ONNX Runtime 发出 provider 分配警告 | 日志记 CUDA_with_CPU_fallback，per_node_provider_verified=false | 不声称所有算子均在 GPU 上执行 |

## 5. 以后做项目要注意什么

1. 时间字段必须带语义、单位和来源。未知采样时间不得补成接收时刻。
2. 默认不替换现场认可版本；先构建独立候选，再做授权的实物验证。
3. 原始记录与分析结果分开保留，脚本拒绝覆盖已有输出；失败/丢失记录也保留。
4. 同步误差、安装符号、标定覆盖与身份误锁不能被单一 RMS 数值掩盖。
5. 构建/回归通过只证明本次软件检查，不证明数据采集开销、抗遮挡性能或硬件安全。
