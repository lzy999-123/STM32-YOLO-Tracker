## 2. 本次学到的知识

- 网络优先级 → 同一 `wpa_supplicant.conf` 保留两个网络块，通过数值决定优先顺序 → 适用于固定地点网络与移动热点的备用连接。已连接热点时，不将“高优先级”理解为首选网络出现后必然立即切换。
- 关联与 DHCP 分开检查 → `wpa_state=COMPLETED` 表示认证完成，电脑能实际发现、访问和解码才证明业务链路可用 → 换网后需要重新确认地址和服务。
- 持续恢复需要守护循环 → 原脚本只等待一次，现脚本继续监测连接并补启动 DHCP → 适用于网络晚于设备上电、DHCP 进程被摄像头服务重启等情况。
- 校验 PID 的实际命令行 → 核对监测脚本、网络接口和进程类型，避免重复启动 supplicant 或误杀其他接口的 DHCP → 可复用于小内存板子的启动服务。
- 管理通道先验证 → 使用专用 SSH 密钥并固定设备主机公钥，实测可用后关闭无认证的网络 ADB → 共享网络部署时保留可核对身份的维护入口。

## 3. 遇到的问题与解决过程

| 现象 | 证据与原因 | 处理方法 | 结果 |
| --- | --- | --- | --- |
| 电脑报告手机热点暂时不可连接 | 用户确认热点一直开启；Windows 网络扫描可能使用缓存，不能据此认定热点关闭 | 刷新原生 WLAN 扫描，并核对实际 SSID 和 DHCP 地址 | 重新连入手机热点，完成备用启动验证 |
| 首次 SSH 密钥登录未通过 | 已确认 `/root` 的属主是 `1005:1005`，不符合 root 私钥登录路径权限要求 | 记录原属主，修正为 `root:root`，目录 `700`、公钥授权文件 `600` | SSH 密钥认证通过，两次重启后仍可访问 |
| 扫描或重配置时控制接口响应较慢 | PONG 暂时延迟不能证明 supplicant 进程消失 | 启动前检查 `/proc` 中的真实进程参数 | 实板重启后仅一个 supplicant 实例 |
| 实验室首次 SSH 和视频访问超时 | 已发现设备地址，后续 6 次 ping 中 2 次超时；无线链路存在短窗口丢包，具体触发因素未定位 | 延长本地维护连接超时，重新核对设备身份和连接状态，再验证解码 | SSH、配置核对及 30 帧解码通过，未宣称长期稳定 |

## 5. 以后做项目要注意什么

- 更改网络前先备份配置并验证维护入口，测试结束必须恢复真实 SSID，读回确认没有测试配置。
- DHCP 地址不能作为固定设备身份；重新发现当前地址，并核对 SSH 主机公钥。
- 先核对电脑当前网络，再检查板子通信；电脑自动切到另一 WLAN 会造成访问旧网段超时。
- 真实 Wi-Fi 配置和维护私钥仅保留在受保护的设备或 Git 忽略目录；临时明文 Windows 网络配置导出文件在验证后删除。
- 脚本启动、认证、地址获取、发现、视频解码分别记录结果；短窗口通过不能替代长期稳定性验收。
