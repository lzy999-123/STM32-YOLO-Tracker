- 涉及模块：仓库外正式 STM32 固件、Luckfox UART 桥接、OLED 字库与渲染、主机回归检查、固件补丁归档

## 1. 本次目标与完成情况

用户要求在下位机 OLED 显示当前连接的 Wi-Fi，PC13 短按切换页面，长按切换自动 / 手动；后续补充要求长名称滚动显示。

已完成源码与软件验证：

1. PC13 使用非阻塞 30ms 消抖与 1000ms 长按判断；短按在松开后切页，长按只切模式一次，松开不再触发短按。上电已按住时等待首次松开。
2. 保留原云台状态页，增加 Wi-Fi 页；名称超过一行时先停留 1500ms，再每 500ms 移动一个字形，循环间留三格。第三行显示模式与控制通信状态。
3. Luckfox 获取实际 `wlan0` 关联名称，每 2 秒探测 / 上报，后台探测超时 500ms；无需 Qt 会话也能显示。读取运行状态，不读取保存的 Wi-Fi 密码。
4. 增加 `0x05` 网络元数据与 `0x84` 固件能力声明，支持完整 32 字节 SSID。能力确认前不向旧固件发送新增元数据；Wi-Fi 数据不刷新控制心跳。
5. 断开时清空名称，报告过期时显示等待更新；故障、急停、校准页优先。PC14 / PC15 操作及模式切换原有运动处理保留。
6. 修改前完整备份外部固件，仓库归档 7 个固件文件的补丁，补充操作与测试说明。

没有完成：Luckfox 实板部署、STM32 烧录、实体 PC13 和真实 OLED 的显示验收。

## 2. 本次学到的知识

- 短按与长按互斥 → 按住到阈值后记录长按已消费，松开不再发短按 → 可复用到菜单 / 控制共用按键；不能在按下瞬间先执行短按。
- 网络状态与运动控制链路分离 → 无上位机会话时也能显示 Wi-Fi，但 Wi-Fi 上报不能延长控制租约 → 可复用到电池、温度、网络等旁路遥测。
- 字形宽度与 UTF-8 字节长度不同 → 现有汉字占两格，滚动先解码并查字库再移动字形 → 避免截断汉字和绘制半个字。
- 协议兼容需要确认接收端语义 → 老固件的未知 TYPE 会刷新链路时间 → 用新固件能力声明决定是否发送新帧。
- 构建与硬件证明分开 → 真实 C 代码在主机执行能够验证逻辑和目标缓冲区 → 仍需实体按键及 OLED 确认触感、刷新和可读性。

## 5. 以后做项目要注意什么

1. 按键长短按共用时，短按放在释放阶段，长按消费状态必须跨释放保留。
2. 查 Wi-Fi 状态要读取真实关联结果；保存配置、电脑 Wi-Fi 或能访问视频都不能直接代替板子当前名称。
3. 新增协议类型前检查旧接收端对未知类型的处理，尤其控制租约与运动使能。
4. 小屏滚动应在 RAM 生成目标字形，保留增量 I2C 刷新，避免阻塞 FOC 控制循环。
5. 仓库外源码先备份，并归档针对明确基线的补丁，避免只保存 HEX 而丢失修改原因。
