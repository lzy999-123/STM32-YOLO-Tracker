## 2. 本次学到的知识

- 仓库外固件需要可审查的修改 → 将针对正式备份的补丁保存到 `board/stm32/patches/`，明确工程入口和适用基线 → 防止只留下本地 HEX 而无法追踪修改。
- 补丁文件需要固定换行 → `.gitattributes` 将固件补丁设为 LF，并对补丁数据关闭源码空白检查 → 保留 unified diff 中合法的空白上下文，避免 Windows 检出转换影响补丁格式；源码仍按原有规则检查。
- Git 归档移动不等于丢失文档 → 五份正文与基线比较一致，修正当前入口链接 → 保留实验过程且保持目录清晰。
- 发布验证按改动风险选择 → Qt 活动源码未修改，检查构建引用并执行 Release 增量构建；桥接与 OLED 执行当前 Python / C 检查 → 不把新的编译结果当成新增硬件验收。
- GitHub 更新包含远程核对 → 提交前远端 `master` 与基线一致，提交后推送并比较 SHA → 区分本地提交和真正发布。
