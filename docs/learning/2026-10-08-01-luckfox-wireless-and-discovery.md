## 2. 本次学到的知识

### 完整链路需要逐步验证

无线视频需要依次完成：识别网卡、加载驱动、连接热点、取得IP、启动RTSP服务、上位机接收和显示。
配置文件存在或驱动加载成功，只能证明其中一环；最终要用真实画面验证图像链路。
这套方法可用于其他嵌入式通信、摄像头和传感器项目。

### 驱动同时依赖硬件与内核ABI

网卡USB ID为 `0bda:0179`，对应r8188eu；板子已有的8188fu不能直接替代。
内核版本号相同也不代表模块兼容：配置、结构体布局、对齐和工具链都会影响结果。
今后安装驱动应先确认硬件ID，再核对内核和构建配置。

### 网络访问失败有多种原因

板子有线地址访问不了，可能是驱动异常，也可能是DHCP清掉了静态IP。
应同时检查接口地址、路由、无线地址和设备进程，避免把“旧地址访问不了”直接判断为死机。

### 初始化时机与执行上下文很重要

发送路径第一次创建AES-CCM会触发需要等待的初始化，而原子发送上下文不能这样阻塞。
把加密器创建提前到模块初始化阶段，配合结构体对齐修正和依赖预加载，解决了实际捕获的相关故障。
这说明实时任务中的复杂初始化应尽量提前完成。

### 自动分配地址与自动发现设备各有职责

DHCP负责分配IP；设备发现帮助上位机取得设备当前地址。
Qt通过发现请求获取板子回应的源地址，再打开 `/live/0`，旧地址失效时仍可重新查找。
这种设计适用于地址会变化的局域网设备。

### 软件需要把复杂配置转化为简单操作

默认“Luckfox 自动识别”，点击按钮完成查找和开流；查找不阻塞界面，并提供取消和失败提示。
用户操作少，需要开发者把状态、超时、异步流程和错误信息处理清楚。

### 测试指标必须与结论对应

收到画面证明图像链路可用；分辨率证明画面尺寸；接收帧数量可能包含缓冲旧帧，不能直接证明编码帧率或低延迟。
端到端延迟需要单独设计同步测量，不能仅凭“看起来流畅”得出结论。

### Git提交也是交付

一个阶段需要保存代码、部署脚本、验证记录和未完成事项。
每次把学习报告与修改一起提交，可以保留决策过程，为最终总结提供连续、可追溯的材料。

## 3. 遇到的问题与解决过程

| 现象 | 证据与原因 | 处理方法 | 结果 |
| --- | --- | --- | --- |
| 现有无线驱动不能用于插入的网卡 | USB ID和驱动支持设备不同 | 匹配r8188eu并构建模块 | 网卡注册与wlan0出现 |
| 注册或收发阶段出现内核故障 | 对比实际内核与SDK的skb、net_device布局 | 修正构建配置并核对偏移 | 对应布局故障解决 |
| 发送加密数据时出现原子上下文调度错误 | 调用链经过CCMP创建、模块请求和等待 | 提前创建AES-CCM、预加载依赖 | 修正后完成无线传输验证 |
| 释放加密器时出现Oops | 实际内核与SDK加密结构对齐不同 | 把CRYPTO_MINALIGN调整为8并重编依赖 | 加密器创建和释放通过 |
| 连接无线后有线访问丢失 | 一次日志无Oops，无线仍可访问；eth0地址被清除 | 避开摄像头DHCP重启，恢复有线静态地址及无线租约进程 | 两个接口在重启后同时正常 |
| 每次填写IP操作麻烦 | 热点地址由DHCP分配，可能改变 | 增加板子发现服务与Qt自动查找 | 点击按钮发现设备并出画面 |

PREEMPT_COUNT不一致曾被当作可能原因，但启用后仍失败，不能将其写成已经证实的根因。
多次断电重试也说明，今后应更早准备持久日志和恢复通道，减少在证据不足时连续试错。

## 5. 以后做项目要注意什么

| 做法 | 本次经验依据 |
| --- | --- |
| 开始前写下验收标准 | “无线出画面”“重启恢复”“点击自动识别”分别需要验证 |
| 一次测试一个环节 | 分开认证、DHCP和视频启动才能缩小故障范围 |
| 先保存日志再做可能导致失联的操作 | 故障后设备无法访问时，持久日志提供定位依据 |
| 把猜测与结论分开记录 | PREEMPT_COUNT猜测不能替代实际调用链证据 |
| 调试时保留独立管理通道 | 有线或串口可帮助读取日志和恢复设备 |
| 把开机恢复作为功能验收的一部分 | 当前运行正常并不证明重启后仍可使用 |
| 小步提交并记录学习过程 | 保存可运行阶段，避免只剩最终代码而丢失修复思路 |
| 保存复现条件 | 内核源码版本、构建配置、工具链、脚本和制品标识都需要记录 |
| 明确本次验证覆盖范围 | 无线视频通过，不等于串口、跟踪闭环和延迟指标全部通过 |

## 6. 当前不足与下一步

- 实际拔掉网线后的持续传输与长时间稳定性尚未在本阶段测试，需要记录时长、重连情况和故障。
- 跟踪与STM32云台联动需要独立验收，包括目标丢失处理、控制响应与安全停止。
- 同步摄像头到屏幕的真实端到端延迟尚未测量，需要制定方法并记录结果。
- 完整驱动重建仍依赖已准备好的SDK环境；当前归档脚本不是全新环境的一键构建工具。
